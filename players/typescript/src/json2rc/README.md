# json2rc — a TypeScript JSON → RemoteCompose converter

A port of the Python `rcj` converter (in the rcJson corpus), which is itself verified
byte-identical against the Java `RemoteComposeJsonParser`. So this one has a hard definition
of correct: **the same JSON in must give the same bytes out**, and nothing is claimed to work
until it does.

Until now there was no converter in TypeScript at all — the TS tree had `rc2json.ts`, which
goes the other way. This closes that, and means the web player can eventually compile a
document in the browser with no toolchain at all.

```sh
src/json2rc/build.sh                                   # -> build-json2rc/
node build-json2rc/cli.js in.json out.rc
node build-json2rc/compare-rcj.js <list> <rcj-out-dir> # the whole corpus against rcj
node src/json2rc/tests/check-paths.cjs                 # the path/loop cases the corpus misses
```

## Where it stands

Measured over the 342-document corpus, against rcj's own output for each:

| | count |
| :--- | ---: |
| **byte-identical to rcj** | **345** |
| differ | **0** |
| unsupported (raises) | **0** |
| crashes | **0** |

The corpus lists 504 documents. rcj itself converts 345 of them; the other 159 it rejects
too, so there is no reference to compare against and they are out of scope for "match rcj".
The harness now prints that number rather than skipping them — see below.

**The whole corpus converts, and nothing differs.** Every one of the 345 documents produces
exactly the bytes rcj produces. Nothing is approximated, and anything
outside the implemented surface still raises rather than guessing — a converter that is
silently wrong is worse than one that refuses, because the document renders and only looks
a bit off.

What converts today: the header, `column`/`row`/`box`/`canvas`/`text`, the modifiers
`fillMaxSize`/`fillMaxWidth`/`fillMaxHeight`/`width`/`height`/`size`/`widthIn`/`heightIn`/
`weight`/`horizontalWeight`/`verticalWeight`/`background`/`padding`/`offset`/`semantics`/
`onClick`/`multiClick` (with all six click actions), linear and sweep gradients, and the
full 3D surface — `camera3D`, `lights3D`, `matrix3D`, `drawMesh3D`, `meshPrimitive3D` (all
23 primitives), `meshExpression3D` (all four surfaces), `defineMesh3D`, `material3D`,
`depthBias3D`, `clearDepth3D`, `vectorExpression` and `touchExpression`; the particle system
(`createParticles`, `particlesLoop`, `particlesComparison`), `impulse`/`impulseProcess`, the
`spacer`/`flow`/`fitBox` components, and the `visibility`/`clip`/`border`/`verticalScroll`
modifiers, the
paint bundle (colour, style, alpha, stroke width/cap/join, text size), the common draw
commands, the matrix stack, `loop`, `conditionalOperations`, paths (`drawPath` from an SVG string, `pathCreate` /
`pathAppendLineTo` / `pathAppendClose`), `variable` and `resources.variables` including
deferred materialisation, and the full expression compiler — operators, 43 functions, 107 system
variables, `componentWidth()`/`componentHeight()`.

## Bitmaps

`resources.bitmaps` declares named images and `texture3D` references them by name. Whatever
the source, the bytes are embedded in the `.rc`: a document that still needs an external file
to render is not a document.

```json
"resources": {"bitmaps": {"checker": {"base64": "iVBORw0KGgo…"}}},
…
{"texture3D": {"bitmap": "@checker"}}
```

`{"file": "textures/checker.png"}` works too, as does a bare string in place of the object.
Width and height are read from the PNG's IHDR rather than declared — an author who has to
restate them will eventually restate them wrongly, and the image would then sample against
the wrong grid with nothing to say why.

**`file` needs a reader.** The converter core has no filesystem dependency on purpose, so
the caller supplies one:

```js
convert(json, {readFile: (p) => new Uint8Array(fs.readFileSync(path.resolve(dir, p)))})
```

Without it, `file` raises rather than quietly producing a document with no image in it.
Base64 needs nothing — the decoder is written out rather than borrowed from `atob` or
`Buffer`, so the converter still runs anywhere.

Two base64 spellings are accepted here that the reference rejects outright: a `data:` URI
prefix and the url-safe alphabet (`-`/`_`). Both make rcj raise, not miscompile, so this only
ever turns an error into a correct document — but it is a real difference in what converts,
not a shared behaviour. Plain and whitespace-wrapped base64 are byte-identical on both sides.

`url` is deliberately *not* accepted for a bitmap, because the reference does not accept it
either — it fetches sounds from a URL but not images, and adding it here would diverge.

## What is still not implemented

Nothing the corpus reaches. Beyond those, the reference itself has commands neither converter implements;
`docs/JSON_GAPS.md` in the rcJson corpus is the list, generated by probing rather than by
hand.



## Why there is a separate path test

The corpus sweep is the main check, but it cannot cover paths. Of 342 documents only six
reach `drawPath` and byte-compare — **none of them with a `C` or `Q` curve verb, and none
with a named `$paths.` reference**. Every document that does use a curve is blocked by some
*other* unsupported feature, so those branches never execute during the sweep. The corpus
would have reported a clean 342 with the entire curve half of the SVG parser broken.

The same held for the two most recent additions. Of the corpus documents that reach
`conditionalOperations`, only the `lt` and `eq` conditions ever run — `gt`, `ge` and `le`
never do, and the mapping (`gt:4, ge:5, lt:2, le:3, eq:0`) is not sequential, so a
transcription slip in it would have gone unseen. `offset` is reached by two documents, both
using the list form; the `{x, y}` form was never executed.

`tests/check-paths.cjs` is 232 small documents covering M/L/H/V/C/Q/S/Z, coordinate runs,
multiple subpaths, `pathCreate`, loops (nested, stepped, and shadowing an outer variable),
SVG arcs, bitmaps in every declaration form, all five conditions plus the unknown-condition fallback, both `offset` forms, every
`semantics` key, both `onClick` shapes and all six actions, the gradient variants, the
sizing and weight modifiers, an argument-evaluation-order case for every multi-argument
command, and the 3D surface (every primitive, every mesh-expression surface, every matrix
op, every render mode, every touch stop mode) — each byte-compared against rcj.

The 3D half needed its own coverage for the same reason. The corpus exercises 14 of the 23
primitives and never uses the `general` mesh-expression surface at all — the one branch that
takes three separate coordinate expressions — nor `scale`/`multiply` matrices, nor an
orthographic camera, nor 11 of the 14 render modes. It was checked by breaking it on purpose: swapping the quad verb
tag catches 2 cases, dropping the `S` control-point reflection 1, changing the loop's default
step 4, mis-tracking `H` 1, swapping `ge`/`le` 3, writing the condition type as an int
instead of a byte 8, swapping `offset` x/y 3, and dropping its missing-key default 1.

## The port's own hazards

Twenty-two hazards, every one invisible without byte comparison — each produced a document that
converted without complaint.

**A harness that skips is a harness that lies.** `compare-rcj.js` did
`if (!fs.existsSync(ref)) continue` for a document with no reference, and printed a total
that looked whole. 162 of the 504 listed documents were being left out of every number it
reported — 159 legitimately, because rcj cannot convert them either, and three because the
reference generation had not passed a `base_dir` and so failed on exactly the bitmap
documents this section adds. The counts above now include the unreferenced total, and it was
looking into bitmaps that surfaced it rather than any check designed to.

**The verbose resource form is not a stylistic alias.** `[{"name": n, "value": v}]` and
`[{n: v}]` are different shapes, and an array entry carrying a `name` key must be read as
the former. Treating every key of every entry as its own resource turned one bitmap into two
called `name` and `value`, and the first tried to open a file called "tex".

**Arcs are lowered at authoring time, and the rounding is load-bearing.** The player has no
arc primitive, so `A`/`a` is decomposed into cubics here. The reference narrows each emitted
control point to float32 (a Java `(float)` cast) while keeping the rest in double —
`Math.fround` in the port. That looks cosmetic, since every value is written as float32
anyway, but the narrowed endpoint becomes the *start point* of the next segment, so rounding
it late changes the geometry downstream. Dropping the narrowing changes exactly one of the
eighteen arc test documents, which is the kind of margin that never shows up in a rendering.

**A field that takes no expression must refuse one, not coerce it.** `padding` and `weight`
go through the reference's getDouble path, where Python's `float("2+2")` raises. `Number`
returns NaN instead, so an expression written into an object-form padding was emitting a NaN
where the reference refuses the document outright. Found by a mutation that changed no bytes
— the only reason to look at it at all.

**A test that both converters reject proves nothing.** Two rounds of test generation
produced documents that failed identically on both sides and so "passed": nine sizing
documents used `content` where a container wants `children`, and seventeen 3D documents
omitted the `primitive` key entirely. Every new fixture is now checked to convert under rcj
*before* it is compared, and the mutation pass is what surfaced both.

**Argument evaluation order is observable.** Resolving a deferred variable emits its
expression op at the moment it is resolved, so the order a command reads its fields in is
the order those ops appear. `rotate` reads its angle *first* and its pivots second; reading
the pivots first reordered three expressions in one document and changed 1800 bytes of tail.
Nothing about the command's own encoding was wrong. Every multi-argument command now has a
test that declares each argument as a deferred variable in reverse order.

**A childless container needs `children`, not `content`.** This one broke a *test* rather
than the converter: nine sizing documents used `content`, both converters dropped every
child, and the suite passed 79/79 on documents that exercised nothing. Four mutations to the
weight and sizing code changed no bytes at all, which is the only reason it surfaced.

**A bare scalar under `drawPath` means `path`, not `value`.** `_normalize_command` special-cases
exactly two commands, `drawPath` and `pathAppendClose`: everywhere else a scalar becomes
`value`. Missing that, `{"drawPath": "M10 20 …"}` read `command.path` as `undefined`, and the
SVG parser dutifully reported that it does not support the path command `'u'` — the first
letter of `"undefined"`. The corpus never caught it, because all six of its byte-comparable
`drawPath` documents use the object form.

**A missing required field is an error, not a NaN.** rcj indexes `command["cx"]` and raises
`KeyError`; the port called a helper that mapped an absent key to NaN, so a typo'd or
misspelled field converted happily into a circle drawn at NaN — invisible, no diagnostic.
Required fields now raise and optional ones ask for absence explicitly. Making this strict
changed nothing in the corpus, which is the point: it only fires on documents that are wrong.

**`class NotImplementedComponent extends Error {}` has `name === "Error"`.** An empty
subclass inherits `name` from `Error.prototype`, and the harness splits deliberate refusals
from real crashes on exactly that field — so every refusal was being counted as a crash. The
converter was fine and the scoreboard was not, which is the harder kind to notice.

**The root has no content op.** A column emits `LAYOUT_COLUMN` then `LAYOUT_CONTENT` and
closes with two ends; the root emits neither and closes with one. Getting that wrong shifted
every component id by one.

**A text component is a container.** `CoreText` is followed by a content op and two ends. It
looks like a leaf and is not.

**A canvas allocates two component ids**, not one: a plain content op *and*, at apiLevel ≤ 7,
a canvas-content op — so it closes with three ends. Emitting two cost 20 documents on its
own, and the symptom was a single missing trailing byte.

**A bare-string modifier carries a NaN sentinel.** `"fillMaxSize"` means
`{"fillMaxSize": "NaN"}`, not `1.0`. Using 1.0 produced a width modifier that read as
"exactly one pixel" and converted without complaint.

**A childless box defaults to centre/centre**, where the container form defaults to
start/top.

**`save` is a container**, not just an op: `{"save": [ … ]}` saves, runs the nested commands
and restores. Treating it as a bare op silently dropped everything inside it.

**`matrixScale` writes four fields** — sx, sy and a pivot defaulting to NaN. Writing two lost
eight bytes in six documents.

**The direct-key paint form emits in a fixed order** (`shader, color, strokeJoin, strokeCap,
style, width, textSize, sweepGradient`), not the order the keys appear in the JSON. It also
has aliases (`strokeWidth` -> `width`) and three keys the reference silently ignores as
direct keys — those now raise instead of being lost.

**A library entry wraps its document under a `json` key.** Without unwrapping, the parser saw
no `root` and emitted a bare 17-byte header — a valid file containing nothing.

**A colour reference is a different op from a colour.** `"$colors.ink"` as a paint colour
takes `PB_COLOR_ID`; as a background it takes a by-id modifier with flags=2 and no RGBA; as a
text colour it sets the CoreText `colorId` tag and leaves `color` at its default. Each wrong
form converts happily and renders black.

## Notes on the port itself

The expression tables — operators, functions, system variables — are **generated from
`expr.py`** rather than retyped, so they cannot drift from the Python.

NaN-boxed ids are carried as raw `number` bit patterns everywhere and never round-tripped
through a float. A NaN payload does not survive canonicalisation, and the id inside it is the
whole point.

`build.sh` emits CommonJS into `build-json2rc/` with its own `{"type":"commonjs"}`, because
the package is `"type": "module"` and the output would otherwise be loaded as ESM and fail on
`require`. The converter itself has no dependencies and uses only `Uint8Array`, `DataView`
and `TextEncoder`; the CLI is plain JS so that no `@types/node` is needed.
