# Findings from building the example catalog

Building each catalog example (see `EXAMPLES_TAXONOMY.md`) runs its document through json2rc,
the Java reference parser (`players/conformance/java-json.sh`, byte for byte), both players,
the Java reference layout (`java-layout.sh`) and the audit. Anything that disagrees is recorded
here with a minimal reproduction. Status: **open**, **fixed** (with where), or **upstream**
(a bug in androidx's reference, to report there; the catalog works around it).

Started 2026-10-29.

## Semantics worth knowing (not bugs)

Recorded as `pitfalls` in the examples that hit them.
- `clamp(min, max, value)`: the value is **last**. `clamp(x, 0, 1)` is always 0.
- `step(x, edge)` returns `x > edge`. `fract` truncates (negative for negative x).
- `splineLoop` only wraps t into 0..1: repeat the first value at the end of the array.
- `seed(s, expr)` seeds the generator, then evaluates `expr`.
- `timeInSec()` is the second within the hour (605 at 10:10:05), not since midnight.
- textFromFloat's default flags pad trailing zeros with spaces ("36605.0 "); flags 3 or 7 avoid it.
- A string `clock` is local time; a countdown to a UTC moment needs an epoch-ms clock.
- `resources.colors` and `floatArrays` are exported by default, `resources.variables` are not.
- `PROFILE_LOW_POWER` (0x8, RcProfiles) is only declared: no operation map, writer or player
  reads it, so a low-power or monochrome look can't be selected through the header profile.
  The players also have no third theme. The component library's mono look is a build-time
  choice (`"componentTheme": "mono"`). A run-time switch, with both looks in one document and
  each under a `visibility` bound to an exported int the host sets (checked in C++ and
  byte-identical to Java), costs +74% over the light/dark document across the 20 component
  demos (Switch: 2048 B to 3827 B). A per-paint alpha overlay would cost less, but it has to
  repeat every coloured paint, because JSON has no colour expressions.
- `drawTextAnchored` `panX: -1` puts the text to the right of x.
- Desktop org.json reorders keys (a HashMap); a device keeps insertion order. The Java reference
  is built against Android's org.json for that reason.
- `weight` is the **horizontal** weight. In a column, the child that should take the height
  that is left needs `verticalWeight`. With `weight` there, Java (and both players) give
  `[{"weight":1}, …]` a 0 width, `["fillMaxWidth", {"weight":1}]` a 0 width as well, and a
  weighted box whose child is `fillMaxSize` takes the whole remaining height, so the fixed
  siblings after it get 0 high (`java-layout.sh`: column [box h50, box{weight 1, fillMaxWidth}
  + fillMaxSize canvas, box h50] at 300×300 gives the last box h=0, and with `verticalWeight` it
  gives 50 / 200 / 50). It looks right only when the weighted child is the last one. CMP-09 and
  the chart demos use `verticalWeight`.
- A canvas `loop` replays its commands, transforms included: a `rotate` in the loop body
  accumulates over the iterations (inside one `save`). DonutChart uses it as a running sum:
  each slice is drawn from 12 o'clock, then the canvas is rotated by its angle (byte-identical
  with Java, same in C++ and TS).
- Component locals that read only a document float array (`"lo": "arrayMin(@values)"` with
  values = `"@visits"`) are inlined at every use instead of becoming one resources.variables
  expression: components.mjs counts only `resources.variables` as names a resource expression
  may read, not `resources.floatArrays` (which json2rc and Java accept there, EXP-08). Adding
  them would save about 70 B per Sparkline call (2601 B to about 2460 B for its demo); not
  changed, the charts work either way.
- A component param default is used as written: `"default": "@theme.text_md"` is not
  substituted (json2rc: "Unknown token in expression: @theme.text_md"). Give the number
  (DateLabel's fontSize defaults to 15). `lintComponent` used to warn about names a body
  defines itself (a text op's `varName`, a tree `variable`, a `textMeasure` name) as if every
  caller had to declare them; it now counts them as bound (DateLabel).
- A layout `text` can show a substring after all (the U32 workaround): put textSubtext /
  textTransform in the `global` section of a 0-size canvas and give the layout text
  `"@varName"`. The global section is written before the root, so the text variable exists when
  the text reads it. Byte-identical with Java; C++ and TS both draw the weekday from
  `textSubtext {"text": "Monday   Tuesday  ...", "start": "(weekDay() - 1) * 9", "len": 9}` then a
  trim (operation 3), and the next text in the row follows the trimmed width. Seven names cost
  about 180 B that way against 713 B for TextChoice's one-text-per-item (about 90 B per item),
  so it is the choice for long lists; TextChoice needs no padding and takes any index expression.
