## 2. Dead ends and wasted calls
- **Call 18** (sea = surfaceHigh): a guess at a theme colour. Knowing the theme's actual light and dark hex values per role (track vs surfaceHigh) would have avoided it. build_kit lists the names only.
- **Call 12 → 13 → 14**: my own night colour silently dropped the mono night shade. The WorldMap pitfall says "in mono ... the night a grey shade", but it does not say that passing nightColor replaces it. One dead end.
- **Call 16** was needed only because the MAP-01 snippet uses flags 4 (no padding) for hours and minutes, so it shows "10:5". A correct example would have avoided it.
- Calls 11 and 12 both spent effort on the server-time-zone surprise (see 3).
Dead ends: 2 (calls 18 and 12's mono regression); call 16 was a near-waste.

## 3. Wrong, misleading, noisy or missing
- **MAP-01 time format is wrong**: `"whole":2,"decimal":0,"flags":4` for both hours and minutes; the reference says "4 none", so 10:05 UTC prints "10:5". Its "verified" note picks 10:30, which hides it.
- **WorldMap's default night colour is wrong in dark theme**: `"nightColor" default "@colors.onSurface"` at 0.25 makes the night side LIGHTER than day in dark mode (the default dark render looks like a lit band). No pitfall mentions it.
- **nightColor overrides mono**: the pitfall "In mono the land is an outline (no fills), the highlight a fill, the night a grey shade" is true only while nightColor is left at its default.
- **The render clock is local to the server's zone** and is not stated: "pin it with system_variables {"10": 0}" appears only in the expressions reference, about UTC days. A clock like "2026-10-31T14:30:00" rendered as night for Lyon until I pinned offsetToUtc. render's description should say which zone `clock` is in and that offsetToUtc comes from the server.
- **The fitBox reference paragraph is garbled**: `"fitBox": {"modifiers": ["fillMaxSize"], "children": [{"column": {"modifiers": ["fillMaxWidth", {"height": fillMaxWidth alternatives and theme colours). The first child...` and "alternatives hold texts, switch layouts with a stateLayout" begins mid-sentence. The query snippet seems to be built from broken or interleaved lines.
- **WorldMap bytes**: the doc says "a world is ~3.5 KB"; inspect bytes shows the outline PathData at 5,681 B (low detail, land).
- **WorldMap fills the width**: in a row it took all of it and the weighted text column got 0 width. The params say only "scales to fit the box it gets"; nothing says it is fillMaxWidth.
- **variants has no phone-screen size** (2x2, 4x1, 4x2, narrow, wide, short, tiny); I had to render 400x800 separately.
- **variants "seven hours later"** is useful, but it cannot pin offsetToUtc per clock: a June and a December date in a DST zone need two calls.
- **Noise**: convert's host_variables lists my themed colours (`mapLand (color) = "#FF3A475C"`, dark side only) as "Host-settable", which reads as if they were intended host inputs.
- **TextChoice vs a word in a sentence**: guidance is spread over three places (TextChoice pitfalls, format reference, TIM-11). It works, but the padded-string trick is manual.
- The audit gave 0 findings for literal hex colours in resources.colors (themed). That is probably right, but the design rule "literal hex colours lock one look" suggested otherwise.

## 4. What I would have liked
- A WorldMap output (or a documented expression) for "is it day at (lat, lon) now" and "the longitude where it is midnight now", so the words cannot disagree with the shade. I wrote the solar declination, hour angle and equation of time myself (the map does not use the equation of time; up to ±16 min of difference).
- WorldMap `label` accepting a text object, so the live description goes on the map itself instead of on a wrapping box, with the map's own "World map" label left over.
- A night colour default that darkens in both themes (e.g. a theme "scrim" colour), and mono kept when the colour is overridden.
- render `sheet: true` with clocks returning one captioned contact sheet (I stitched locally), and per-clock `system_variables` or a `timezone` option ("Europe/Paris") that handles DST.
- A theme palette table with hex values (light, dark) per role.

## 5. Honest assessment
- **Correctness**: the night shade comes from WorldMap (declination from the day of the year, sun longitude from UTC). The city's state comes from my own solar elevation with the equation of time: night below -6°, twilight -6° to -0.83°, daylight above. Checked against known sunrise and sunset times for Lyon (Oct, Dec, June) and Sydney (June, Dec): all plausible within minutes. Midnight-longitude words are 8 sectors of 45° ("the Pacific", ..., "Asia and the Pacific"), so they are coarse.
- **Host variables**: `city` (string, "Lyon"), `lat` 45.76, `lon` 4.84. Local time = the device clock (timeInHr/timeInMin). Assumption: the user's city is in the device's time zone; there is no city time-zone variable.
- **Sizes**: a stateLayout by windowHeight(): under 130 dp a compact row (map + city/time/state word); 130–300 the 4x2 column (map 96 dp + city/time + status line); over 300 the phone layout (map 170 dp, centred vertically). 4x2, 4x1, 2x2, narrow, wide and short render clean. At 180x102 "16:30" is clipped. Medium at 576x128 falls to compact (fine). The phone layout leaves empty space (map height is static).
- **Themes/mono**: light, dark, mono-dark and mono-light all readable after the own themed colours (mapLand, mapSea, nightShade with mono values). Dark contrast of the night side is still modest.
- **Repaint**: scheduled once a minute (inspect runtime).
- **Accessibility**: live contentDescription on the map box. The texts are readable nodes. There is a redundant inner "World map" label.
- **Bytes**: 12.4 KB. Three WorldMap instances share one path (5.7 KB), and each adds a pathExpression and loops.
- **Weak spots**: region words are coarse; I added "twilight", which the user did not ask for and the map does not draw; the time is 24 h only (no locale); the colours are literal hex (themed); the night alpha (0.5) is one value for both themes; the map does not use the equation of time while the words do.
