# Solar widget: eval notes (prompt 41, run 1)

Final document: `solar.json` (source, generated by `gen.py`), binary `solar.rc` (11,543 bytes).
Contact sheets: `v4-sheet.png` (all variants), `s13-sheet.png` (noon / huge / 999.6 W / 9.996 kW),
`sc-sheet.png` (night, morning with bad data, evening), `morning-sheet.png` (morning, corrected data), `out/v5-360.png`.

## Decisions
- Host data (all exported): `powerKw` (float, kW), `energyKwh` (float), `price` (float, per kWh), `currency` (string,
  root variable, shown as a prefix: "€6.77"), `prod` (float array: 33 samples every 30 min, 05:00 to 21:00, kW).
- Data contract: the app writes measured samples for past slots, and fills the current and every future slot with the
  latest value (the document hides the future anyway). If future slots are 0, the spline already bends down towards 0
  between the last sample and now (seen in the morning test), so this contract matters.
- Fixed daylight window 05:00 to 21:00 (axis 5, 9, 13, 17, 21). Not per-season; noted as a weak spot.
- Money saved = round(energyKwh * price * 100) / 100, shown with 2 decimals and thousands grouping (flags 535).
- Power: "640 W" under 1 kW (rounded), "4.45 kW" under 10 kW, "12.3 kW" under 1000 kW, "12.35 MW" above; four texts
  switched by visibility, with rounding flag so 0.9996 kW reads "1.00 kW" not "1000 W". "Producing now" / "Not producing".
- Curve: LineChart in function mode, `fn = arraySpline(@prod, clamp(0,1,(u-300)/960)) - @hide * step(u, @now + 1)`, i.e.
  the future is pushed far below the plot and the plot's box is clipped, so the future part is empty. Area wash off
  (see dead end 3). now = timeInMin(), y_max = max(1, arrayMax(prod) * 1.1).
- Layouts by a stateLayout on the window: wide (>=239 wide and >=130 tall): left column + chart with own axis row;
  compact (narrow, 2x2): collapsibleColumn, chart 36 dp then energy then status dropped first; strip (wide but short,
  4x1): icon, power, saved, chart without axis.
- Inline components: PowerNow, Status, Saved, Energy, Header (each used in 2-3 layouts).

## 1. Tool calls (25)
1. `list` - discover servers/tools. Took the 5-step workflow; build_kit first.
2. `build_kit` (user's sentence verbatim) - got Card, LineChart (with now marker, fn mode, pitfalls), Icon, TIM-13 tide
   example, design rules (stateLayout / collapsibleColumn for sizes, compute now from clock). Decided: LineChart + TIM-13 structure, no Card.
3. `get TIM-13 parts json` - to copy host array / string variable syntax and LineChart call. Took `export: true`, root string variable.
4. `reference expressions` - step(x, edge) semantics (value first), ifElse order, 32-entry limit.
5. `reference format` - host numbers in resources.variables, textFromFloat flags (7/23 money, 16 grouping, whole is a max),
   money in cents, visibility needs declared 0/1 variable, widget sizes 320x160, stateLayout/fitBox advice.
6. `convert check:true` - v1 converts (9.7 KB), no findings.
7. `render variants` v1 - future drawn as a flat zero line with a cliff at now; short/4x1/wide-short overflowed.
   Decided: push future below plot; add strip layout for short heights.
8. `render variants` v2 - the masked line and area are drawn outside the canvas (through the axis labels, area as a
   rectangle). Decided: clip a box around the chart, own axis row.
9. `render variants` v3 - clip works but a thin area band remains in the future (area fills to a plot bottom inset above the box edge). Decided: area off.
10. `describe render` - to learn whether samples can carry a clock (they cannot; clock is separate).
11. `render samples @13:00` - noon, huge (12.35 MW / €30,617.27), 0.9996 kW, 9.996 kW. Huge values clipped. Decided autoSize.
12. `render samples @13:00` again - autoSize fixed clipping; formats OK (1.00 kW, 10.0 kW, 12.35 MW).
13. `render night 02:00` - 0 W, Not producing, €0.00, empty curve. OK.
14. `render morning 09:30` - curve drops to 0 at now. (My data bug: 9 samples only reach 09:00.)
15. `render evening 20:45` - 50 W, full curve, now at the right edge. OK.
16. `render samples` impulse/cloudy/hold at 09:30 - to understand the drop; hold-filled future looks right.
17. `render` a probe doc printing arraySpline values - mapping is index = t*(n-1), so the drop was my data; confirmed contract.
18. `render samples 09:40` - zero-filled vs hold-filled future: zero future dips before now; hold is right. Contract fixed.
19. `audit` - 1 info (nesting depth 9). Nothing else.
20. `inspect accessibility` - found my semantics contentDescription "@powerDesc" (undeclared variable) read literally. Removed it.
21. `render variants` v4 - all 12 looks clean, no findings.
22. `render sizes` without variants - silently ignored, one 320x160 render. Wasted.
23. `render variants + sizes` - all extra sizes written to the same `out/v5-size.png`; only 110x110 kept.

## 2. Dead ends and wasted calls
1. Flat zero line for the future (call 7): LineChart has no "draw up to x" option; the kit's `now` marker doc implies
   a marker only. A `until`/`clip_after_now` param would have avoided calls 7-9.
2. Unclipped canvas (call 8): nothing says a LineChart canvas draws outside its box; I assumed clipping.
3. Area band (call 9): the area fills to the plot's inner bottom, which is inset from the box; unknowable without the definition.
4. Morning "bug" (calls 14, 16, 17, 18): mostly my own data mistake (9 samples), but the zero-future dip was real and
   led to a data contract. A sentence in LineChart's pitfalls ("unknown future samples bend the spline; send the last value") would help.
5. `sizes` without `variants` (call 22): silently ignored; then (call 23) overwritten files.

## 3. Wrong, misleading, noisy or missing in the tools' output
- render `sizes`: "With variants: extra [width, height] sizes" - without variants it is silently ignored (no warning),
  and with variants every size writes `out/<stem>-size.png`, so all but the last are overwritten while the log lists
  four different sizes pointing at the same file.
- convert/audit/inspect accept `"contentDescription": "@powerDesc"` (a name that is not declared) and turn it into the
  literal text "@powerDesc"; only inspect accessibility revealed it. convert check should flag an "@name" that resolves to nothing.
- LineChart `now` doc: "a vertical line and a dot on the curve" - the dot is a two-point stroke, so with a masked fn the
  second point goes off the curve and draws a vertical segment from the dot downwards (visible in every render below the dot).
- LineChart says it "fills its width" and derives from componentWidth, but not that drawing is not clipped to its box.
- build_kit matched "panel" to Card ("term": "panel" -> component:Card) - "solar panel" is not a UI panel; noise.
  "money" and "produced" unmatched; nothing on currency formatting in the kit (it was in reference format, which is good).
- build_kit's layout_model is TIM-08 (a countdown) while TIM-13 is the real match; fine but confusing.
- reference format says step(x, edge) "1 when x > edge"; build_kit's TIM-13 text uses step(@now, @t0) consistently. OK.
- render: `findings: none` on v1 where the future drawn as a flat line + cliff - expected, a design issue not a sanity one.

## 4. What I would have liked
- LineChart `until` (or `values_until_now`): draw the curve and area only up to an x, leaving the rest empty. This is the
  standard "today so far" chart (energy, steps, spending).
- A note that canvases do not clip, and a `clip` param on LineChart.
- render: samples that can each carry a clock (scenarios are value + time pairs), and distinct file names for `sizes`.
- convert check warning for undeclared "@name" references in text values / contentDescription.
- A ready formatter for units with auto-prefix (W/kW/MW) and currency; I built four switched texts by hand.

## 5. Honest assessment
- Correctness: values correct at all tested points (0 W, 640 W, 50 W, 1.00 kW at 0.9996, 10.0 kW at 9.996,
  12.35 MW; €0.00, €0.28, €6.77, €30,617.27). Money is computed in cents in the document. Now is timeInMin(), so the
  marker and the hidden future move by themselves.
- Host variables: powerKw, energyKwh, price, currency, prod (33 x 30 min, 05-21). Future slots must hold the latest
  value (contract), otherwise the curve dips just before now.
- Sizes: 4x2 (320x160) main; 2x2 (160x160) compact with a small curve; 110x110 and 230x96 drop the curve; 4x1 strip;
  360x360 works but the chart gets very tall (no dedicated tall layout).
- Themes: light/dark from theme colours; mono-dark and mono-light render cleanly (line in onSurface).
- Accessibility: header description, the chart's label, all numbers are layout texts. Axis labels are bare numbers
  ("5", "9"...); no combined "power now" announcement.
- Bytes: 11.5 KB (three layouts; LineChart expanded per call, ~1.5 KB each).
- Weak spots: fixed 05-21 window (no season / sunrise from the app); vertical segment under the now dot; no area wash;
  axis labels are my own spaceBetween row, so they are approximately (not exactly) under their hours; compact and strip
  charts have no axis; "kWh" text not switched to MWh for huge values (grouped instead); currency always a prefix.
