# Plant care widget: notes

Final document: `plant.json` (generated by `build.js`; converted to `plant.rc`, 14,845 B).
Component under test on its own: `moisture-gauge.json`. Renders: `final-*.png`, `samples-sample*.png`, `sq-*`, `tiny-*`, `yr-*`, `leap.png`, `mono-needs.png`; contact sheets `sheet-*.png` (I put them together locally with PIL).

Decisions
- Host data: `plantName` (string), `moisture` (%), `lux`, and **`wateredDay` = the local date of the last watering as an epoch day** (days since 1970-01-01, i.e. Java `LocalDate.toEpochDay()`). It's a small integer, so a float holds it exactly. `epochSecond()` is out because the reference says Android doesn't know it. The document works out today's epoch day from `year()` and `dayOfYear()` (Gregorian count, split into two variables to stay under 32 entries). `days = max(0, today - wateredDay)`.
- I also added `moistLo`/`moistHi` (the plant's ideal band, default 40–70) and `waterEvery` (default 7 days) as host values, because the band and the interval depend on the plant.
- Sample values: Monstera deliciosa, 52 %, 8,500 lx, watered 3 days ago (as of 2026-10-31).
- Light words (lux): Very dark < 50, Low light < 500, Medium light < 2,500, Bright < 15,000, Full sun. The bar is on a log scale (log10(lux)/5).
- Hint logic: dry → "Needs water" pill. Too wet → "Too wet: skip watering". Overdue (days ≥ waterEvery) and not wet → "Needs water". Otherwise "Water again tomorrow / in N days".
- Layout: a stateLayout picked by window size. Wide (w ≥ 240): dial + right-hand column, which is a collapsibleColumn that drops the hint first and the light row next. Compact (w < 240, h ≥ 120): stacked name, dial, light, short watered line, which turns into "12 days, water" in bold primary when water is needed. Mini (w < 240, h < 120): dial + name + short watered line.

## 2. Dead ends / wasted calls
- Call 11: I declared `nextIn` below its readers. My own error. The message even said how to fix it.
- Calls 10, 12 and 14 were partly spent on avoidable problems:
  - spacedBy in a column with a weighted child, which the reference had warned about and I forgot.
  - Texts without an explicit colour. Nothing in the docs says a layout text's default colour is not themed, so I only caught it by eye.
- Calls 16 and 17, shortening texts for the 2x2 sizes, were normal iteration.

## 3. Wrong, misleading, noisy or missing in tool output
- **No contrast check.** At call 10 the dark and mono-dark renders said "findings: none" while the plant name and the watered line were black on #1C2433 and black on black. The reference says "Colours: theme colours ... literal otherwise" but never says that a `text` without `color` is drawn black whatever the theme. The audit's `hardcoded_colors` check doesn't catch an *omitted* colour.
- **build_kit mapped "soil moisture" and "light level" to Gauge** ("term": "soil moisture" → component:Gauge). Gauge's zones are "green, then amber past warnAt and red past alertAt": they only climb, so they can't show an ideal band with "too dry" below it. The kit gave no `needs_component` for a band gauge, so a new user following the kit would ship a moisture dial that turns red when the soil is wet and green when it is bone dry. Mapping light level to a 0–100 Gauge also makes little sense for lux.
- `not_covered: "calendar arithmetic"`, and the expressions reference covers "a date N days away (|N| < 28)". Neither covers the common "days since a stored date" case, and neither says what form a host should send a date in. I worked out epoch-day arithmetic myself (the leap-year rules fold in).
- Noise:
  - The json2rc error was repeated identically for all 12 variants.
  - render prints "png_path: leap.png (on the server)", which is ambiguous: the file is in my folder.
  - The audit's "Deep Nesting ×5" info appears on a normal 4-level widget built from library components.
- Text in a semantics description can't include a TextChoice word, so the dial's label can't say "OK"/"Too dry". The reference doesn't say how to put a runtime-chosen word into a contentDescription. TIM-11 is mentioned for layout text, but not for semantics.
- Small: in variants, the "narrow 230×160" size sits exactly on a natural threshold. It isn't labelled as "2x2 wide" or similar, so it's unclear which Android cell size it represents.

## 4. What I would have liked
- A render/audit finding for text contrast below ~3:1 (or a text with no colour) in each theme.
- A library "BandGauge" / range-gauge component (value against an ideal min–max). At minimum, build_kit should flag "ideal band / too low / too high" as needs_component instead of matching Gauge.
- A recipe or example for "days since <host date>": the recommended host form (an epoch day) and the today-as-epoch-day expression.
- A way to put a computed word into a contentDescription (TextChoice → text variable).
- Errors that are the same for every variant should be printed once.

## 5. Honest assessment
- **Correctness:**
  - Moisture: status word and band are correct at 4/55/96.
  - Light: words correct at 8 lx and 80,000 lx.
  - Days since watered: today / 1 day / 12 days, plus across the year boundary and Feb 29 2028.
  - Hint logic: dry → Needs water; wet → skip; overdue → Needs water.
  - Plural: "Water again tomorrow" vs "in N days".
- **Host variables:** plantName (string), moisture, moistLo, moistHi, lux, wateredDay (epoch day, local date), waterEvery. The app must send `wateredDay` as a local-date epoch day. If it is sent in UTC, "today" can be off by one near midnight.
- **Sizes:**
  - 4x2 (320×160) is the design size.
  - 512×120, 320×96 and 320×80 drop the hint and then the light row.
  - 2x2 (160×160) uses the compact layout. It has no light bar, and the hint is folded into the watered line.
  - 160×96 and 230×96 use the mini layout: dial, name and days only, with no light level.
  - No render findings at any variant.
- **Themes/mono:**
  - Light and dark are themed.
  - In mono, the band is a thick white/black segment with tick marks at its ends, the value is a filled dot, and the status is a word. Nothing depends on colour.
  - The needs-water pill is a filled face.
- **Accessibility:**
  - The header has a description.
  - The dial has a live description ("Soil moisture 52 percent, ideal 40 to 70"), and every other value is a text node.
  - Weak spots:
    - The status word is a separate node from the dial.
    - The compact layout's "3 days ago" doesn't say "watered" to a screen reader; there is only the drop icon.
    - "lx" will be read literally.
    - Nothing is clickable (no tap-to-open action; I didn't add one because it wasn't asked for).
- **Bytes:** 14,845 B. The 4 Material icons take 3.4 KB, and the dial is expanded 3 times, once per layout alternative (~0.9 KB each).
- **Known weak spots:**
  - At 2x2 the dial is small (~58 dp).
  - The mini layout truncates long names to "Monster…".
  - The marker in the dial can visually sit on a band tick at exactly lo or hi.
  - The light thresholds are my own choice, not per-plant.
