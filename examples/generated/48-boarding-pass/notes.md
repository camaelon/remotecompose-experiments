# Eval 48 run 2 — boarding pass

Final document: `boarding-pass.json` (generated by `gen.mjs`), binary `boarding-pass.rc` (24,146 B).
Renders in `out/`. Tool outputs saved as `NN-*.txt`.

## 1. Tool calls (remotecompose server, in order)
1. `list` — learn the tools. Took the 5-step workflow (build_kit → components → assemble → convert/render/audit → publish). Decided to follow it literally.
2. `build_kit` (goal verbatim) — got LabelValue (built for exactly this: "Gate / B34"), QrPlaceholder, TIM-08 countdown, design rules (state switching by visibility, fitBox/stateLayout for sizes, "A QR code is a drawing"). Decided: LabelValue for every field, QrPlaceholder for the code, compute the countdown in-document.
3. `get LabelValue demo_json` — a ready boarding-pass strip (weighted boxes + 12 dp gaps, string host var syntax). Copied its structure.
4. `get TIM-08 json` — countdown expression style, textFromFloat. Decided host sends boarding day (dayOfYear) + boarding/departure minute-of-day, so the remaining time is `(boardDay - dayOfYear())*1440 + boardMin - timeInMin()`.
5. `reference query` (host vars, visibility, textMerge, TextChoice) — got host float/string declaration syntax and semantics/a11y rules. Visibility syntax was missing from the answer.
6. `get LAY-12` — visibility modifier syntax (0 gone, 2 invisible). Used it.
7. `get TextChoice` — status word by index; noted the "visibility is an INTEGER expression" pitfall.
8. `reference query` (step order, visibility, fitBox, widthIn, flags) — got "visibility takes a DECLARED variable exactly 0/1", textFromFloat flags table (13 = zero padded). Decided: all conditions as named resources.variables; layout switch by `step(windowHeight(), 420)` visibility rather than fitBox.
9. `reference topic components` — inline component syntax (used for one `Countdown` component shared by phone and widget trees).
10. `convert check:true` — converted first try (21,184 B); warning "On time" clipped in the status pill.
11. `render samples` (7 host-value sets, pinned clock 06:20, phone light) — all states correct: 2 h before, 5 min, boarding, after departure ("Gate closed"), gate change banner, delay, long names. Saw: pill clipped, status still "On time" after departure, delayed departure not highlighted.
12. `render variants:true` — dark/light/mono/narrow/wide/short/widget/tablet. Widget and tablet layouts fine; at 259 dp the title wrapped and "CDG" collided with the plane icon. Fixed: derived display status (adds "Boarding", "Gate closed", "Departed" from the clock), an icon per status, "New departure" in error colour when delayed, maxLines on title, smaller codes.
13. `audit` — 0 errors/warnings; 3 infos (nesting, one unused TouchExpression, longest expression 27/32).
14. `inspect accessibility` (gate change) — every field one node ("New gate, K42", "Boards, 07:45"), banner and countdown are texts, QR labelled. Accepted.
15. `render samples` at 320×160 (widget: 5 min, boarding now, closed, gate change, long codes/flight) — all fit.
16. `render componentTheme mono-light samples` (gate change, boarding) — state shown by filled black bars + words, fine.
17. `convert check:true` (final) — 24,146 B, no findings.
18. `inspect bytes` — paths (7 icons) 4.5 KB, float expressions 4.2 KB.

Total: 18 tool-server calls (plus local Read/Bash to view PNGs and stitch contact sheets).

## 2. Dead ends / wasted calls
- Call 9 (`reference topic components`, 27 KB): I needed ~10 lines (top-level `components`, params, body). A `query: "inline component syntax"` would have done.
- Call 8: the first half of the answer was the reference tool's own JSON schema (matched on "query"), not format rules.
- Call 6 (LAY-12) was only needed because call 5's answer omitted the visibility modifier; the next query (call 8) gave the authoritative paragraph anyway.
- No failed conversions, so no hard dead ends. Dead ends: 1 full (call 9 mostly unneeded), 2 partial.

## 3. Wrong, misleading, noisy or missing in tool output
- `reference` fitBox paragraph is garbled — lines from different sentences are interleaved and cut: "{"height":\n  fillMaxWidth alternatives and theme colours). The first child, in order, that fits is shown ... "Use exact HEIGHTS as the thresholds ... a width threshold via widthIn\n  collapsibleColumn ignores its own padding". I could not tell how to do a width threshold, so I used visibility variables instead.
- LAY-12 (the example the guidance sends you to for visibility) uses literal hex colours and an `"integers"` resource, while `reference` says "an "integers" resource reads as 0 in every float expression" and design says never literal colours. Confusing as a model.
- build_kit matched "placeholder" → `use_case:loading-state` (noise) and lists "pass" as unmatched although "boarding pass" is a LabelValue synonym-level use case.
- render `variants:true` / `samples` are described as "in one call", but they write N separate PNGs; there is a `sheet` option nobody explains, so I stitched contact sheets myself with PIL.
- The variants size warning says "at 259×780 the content no longer fits ... or at minimum put the content in a verticalScroll" — the content already was in a verticalScroll; the real problem was two clipped texts.
- `text_overflow "On time" (clipped)` gave no cause; the pill (row with gone icon boxes + TextChoice) wrapped "On time" onto two lines while "Gate changed" fit. I worked around it (an always-visible icon, maxLines 1) without understanding it.
- audit `unused_variables` reports a `TouchExpression` (id 4194304) that the document never wrote — it comes from `verticalScroll`. Noise.
- TIM-08 only shows a countdown to a literal instant; nothing shows how a host should pass a target time (day + minute? epoch?), which is the common case (boarding, delivery, event).

## 5. Assessment
- Correctness: all requested states verified at pinned clock 06:20 with host values: "Boarding in 2 h 0 min" / "2 h 5 min" / "5 min" / "25 min", "Boarding now" (clock or host status 3), "Gate closed" (≤15 min to departure or status 4), status pill "Departed" after departure, gate change banner "Gate changed from K38 to K42" + "New gate" label in error colour, delay pill "+40 min" + "New departure" in error colour. Long name shrinks to fit (LabelValue), long cities ellipsize.
- Host variables: floats boardDay (day of year), boardMin, departMin (minutes of local day), status 0–4, delayMin; strings flight, fromCode/fromCity, toCode/toCity, passenger, gate, prevGate, seat, group, flightDate. Decision: date is a host string (it is flight data, not "today").
- Sizes: phone 360×780 (scrolls), 4×2 widget (≤420 dp tall: compact row with 96 dp QR), tablet (centered 560 dp column — works but leaves empty space; no side-by-side QR). 259 dp-wide phone fixed but not re-rendered after the fix.
- Themes/mono: light, dark, mono-dark, mono-light all checked; states carried by words and filled vs outlined bars, not colour alone. QR stays black on white (lit square in mono-dark).
- Accessibility: header description, each field one node, countdown/status/banner are texts, QR labelled; route reads as five separate nodes ("CDG", "Paris", "to", "JFK", "New York") — weak.
- Bytes: 24 KB (icons 4.5 KB, expressions 4.2 KB) — fine for a full screen, larger than needed for a widget alone.
- Weak spots: "2 h 0 min" not shortened to "2 h"; minute resolution only; departure assumed on the boarding day (± offset within minutes fine, year boundary not handled); "Gate closed" rule (15 min) is my assumption; tablet layout is a stretched phone.
