# Temperature converter (°C / °F): notes

Deliverables: `doc.json` (source, generated by `gen.py`), `doc.rc` (6,946 B), renders in `out/` (`final-*.png`, `w6-sheet.png` for the 4x2 widget at the key values, `narrow-flow.png`), and the tool outputs saved as `*.txt`.

## Design decisions
- **Input control.** The library has two number inputs: `Slider` (drag) and `Stepper` (−/+). There is no text entry. I did not use `Slider`. Its own docs say the thumb is a touchExpression that "starts at the variable's own value and keeps where the finger left it", and the bound variable is written only on release. So a Celsius slider and a Fahrenheit slider can't stay in sync: after you adjust °F, the °C thumb would still show the old value. Two-way editing needs one source of truth that both controls write. I used −/+ `IconButton`s (Material `remove`/`add` icons) under each value. I did not use `Stepper` because it prints its own number, so each value would appear twice and without its unit. Each tap is a finished adjustment, so each tap sends the value to the app. Step: 1 °C or 1 °F. To cover big jumps, there are preset buttons (−40, 0, 37, 100 °C).
- **State.** `c` and `f` are exported floats. A °C tap: `c = clamp(-40,100,c±1)`, then `f = round((c*1.8+32)*10)/10`. A °F tap: `f = clamp(-40,212,f±1)`, then `c = round((f-32)/1.8*10)/10`. Both are computed in the document and shown with 1 decimal (textFromFloat flags 7).
- **App action.** Every control sends a `hostNamedAction` with the current °C value as a float. Each control has its own name (`celsiusMinus/Plus`, `fahrenheitMinus/Plus`, `presetMinus40/Freezing/Body/Boiling`), because the format reference says a shared name breaks (U58). The app gets °C every time; it can read `f` from the exported variable.
- **Visual.** An inline `Thermometer` component: a horizontal tube and bulb on a −40..100 °C scale, filled to the value, with ticks at −40, 0, 37 and 100. Colours are theme colours, sized from componentWidth().
- **Hint.** A `TextChoice` over an index computed from c. The cases: below freezing; 0 °C freezing point; 36.5–37.5 body temperature; ≥100 boiling; −40 "both scales agree". Otherwise it shows "Tap − or + on either value to adjust it".
- **Sizes.** A collapsibleColumn. Priorities: title 1, presets 2, hint 3, thermometer 4; the values and buttons are always kept. At 4x2 (320×160) it shows the values, buttons, thermometer and hint. At 250×110 only the values and buttons are left.
- **Accessibility.** Each value text has semantics "Celsius, 37.0 degrees Celsius" and "Fahrenheit, 98.6 degrees Fahrenheit". The buttons are labelled "Decrease Celsius" and so on. Preset labels include the unit ("37 °C").

## 2. Dead ends and wasted calls (4)
- #10: I used valueFloatExpressionChange for a literal. The reference says "compute one" for that action, but it does not say a literal is rejected. The error message was clear.
- #19: I removed the unit labels and expected the hint to fit, without measuring. A findings line at 320×160 such as "dropped: hint, needs 21 px, 18 left" would have avoided this and #20. The render did not report the collapsed children at all; only the later 250×110 render did (#26).
- #21/#22: The canvas drew text below its own height, and the render did not flag it ("component past its box" did not trigger for a canvas). I found the 2-line wrap only by reading layout heights.
- #25: minFontSize/maxFontSize on a fillMaxWidth text had no effect (+1 byte). Nothing said it is unsupported or ignored.

## 3. Wrong, misleading, noisy or missing
- build_kit resolved "temperature" to `use_case:weather` and listed "unit, converter, celsius, fahrenheit" as unmatched. It offered no example of two-way linked values, which is the core of the request. It suggested the icon `ac_unit` "for unit" and `other_houses` "for other" (noise).
- build_kit offers Slider ("adjust" → Slider) without warning that two sliders bound to one value cannot stay in sync. I learned that only from the Slider definition's pitfalls.
- The format reference says "render variants covers narrow, short, small, tiny and square", but the variants list has **no 4x2 widget size (320×160)** and no square. The "short" variant is 360×384. I had to render 320×160 and 250×110 by hand.
- The render at 320×160 (#18, #19) gave "findings: none" while the hint was dropped. The 250×110 render did report "[collapsed]". This is inconsistent.
- interact reports `"repaint": "continuous"` while `inspect runtime` says "idle — nothing schedules a repaint".
- audit `never_executed` lists every click action op as unreached: "Unreached branches ... or dead code". Noise for an interactive doc.
- The library `Button` is 40 dp tall, and the audit then flags it for "Touch Target < 48dp". The component conflicts with the tool's own rule.
- The accessibility tree shows the thermometer canvas as a node with `"text": "-40°"` (the first drawn label). That suggests a screen reader reads a stray "-40°".
- `zero_size` on the tiny variant is correct, but it explains weights, while the cause was a row of buttons wider than the screen.
- minFontSize is listed under text keys ("auto-shrinks to fit") but had no visible effect here.

## 4. What I would have liked
- A "linked values / unit converter" example or kit entry. Or a Slider mode whose thumb follows an external variable (so two sliders can share a value).
- A Stepper option to show a unit or suffix, or to hide its number.
- 4x2 / 4x1 / 2x2 widget sizes in `variants`, with "collapsed children" findings at every size.
- A finding when canvas drawing goes past the canvas bounds (my tick labels).
- An interact step snapshot (variables after each step) instead of only the final state.

## 5. Assessment of the final screen
- **Correctness.** Verified with interact. C+ updates F; F± updates C; 36→37 °C gives 98.6 °F; −40 °F gives −40 °C; presets set both; °C is rounded to 0.1 after a °F edit. Shown with 1 decimal.
- **Interactions.** −/+ per unit and 4 presets. Every tap sends a hostNamedAction with the °C value. Weak spot: a 1° step makes long trips tedious (from 37 to 80 is 43 taps); the presets reduce this, but there is no drag. That was the trade-off for real two-way editing.
- **Sizes.** Phone 360×640: content sits centred with about 1/3 empty space (the unused_space info). Narrow 259: presets wrap. 4x2 320×160: values, buttons, thermometer and hint. 250×110: values and buttons only. Tiny 180: values clipped (unsupported).
- **Themes and mono.** Light, dark, mono and mono-inverted all render correctly with theme colours.
- **Accessibility.** Values announced with full unit names, buttons labelled, presets include the unit. The thermometer is decorative and its canvas label may leak "-40°". The 40 dp preset buttons are under 48 dp.
- **Bytes.** 6,946 B.
- **Other.** The idle hint is instructional text rather than empty.
