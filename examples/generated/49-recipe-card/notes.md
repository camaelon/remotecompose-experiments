## 2. Dead ends and wasted calls

- Calls 17–18 (+describe): interact action format. The `inspect` summary says "interact (run actions: taps, variable changes…)" without syntax; I guessed `{"tap": {"x","y"}}`. The tool accepted it silently and reported `handled: false` (looked like a layout/hit-test problem, not a syntax problem). A schema error, or the syntax in the tool description, would have avoided 2 calls.
- Call 15→fix: "Step @n. " not substituted. Nothing (lint in check_component, convert) flagged an unresolved `@n.` in a literal text; I only found it by reading the accessibility tree.
- Call 9 was well spent: the sweep showed the ⅞ bug at a tiny amount immediately.
- Calls 11/12: my own errors (spacedBy with a weighted child — the guide warns about it; I missed it in my own component), caught by the render's component_overflow finding which even named the cause.

## 3. Wrong, misleading, noisy or missing in the tools' output

- `zero_size` warning repeated in every render/variant/check for an empty TextChoice item (""), the deliberate "no fraction" state: "1 visible component(s) got no size from the layout, so they draw nothing". It is the right result, and the message suggests weights/collapsible layouts, which are unrelated. Repeated 11 times in one variants call — very noisy.
- `inspect interact` ignores malformed actions instead of rejecting them (see §2).
- `reference query` for "interact actions tap" missed the `actions` param doc of the very tool.
- Literal text with "@n." inside a component body: guide says "`\"... @param ...\"`: inside an expression or text. A number or a variable is spliced in." — it was not, silently. The lint "references that are neither params nor locals" did not fire.
- Locals used only in a dropped `$if` branch are still emitted (audit: 18 unused variables, 379 B dead code). The expander could prune them.
- build_kit `resolved` mapped "steps" → use_case fitness + Steps (a progress-stepper component), "amount" → BigNumber, "adjust" → Slider: all wrong for a recipe; the design rule did the real work. `unmatched_terms` included "recipe", "ingredient", "scaling" yet a recipe-specific rule was present — good, but the component list was noise.
- The shared_string_value warning is good, but it pushed me to change units in the sample data/design (no plural pair for "g"); the advice "give each a distinct starting value … 'unit 1'" would make previews ugly. A way to declare distinct host strings with equal values would be better.
- Variants include "as a 4x2 widget 320×160" and "short" for a scrolling phone screen; harmless but noise for this goal.

## 4. What I would have liked

- The `actions` syntax for interact in the tool list / inspect description.
- A lint for unresolved `@name` in literal texts inside component bodies.
- A per-ingredient formatting component ("ScaledAmount") in the library, since build_kit already has the cook's rule spelled out.
- An accessibility-friendly way to give an ingredient row one spoken label containing the fraction (TextChoice cannot be inside textMerge).
- A "dedupe identical warnings" mode for render variants.

## 5. Assessment of the final screen

- Correctness: amounts scale live (verified at 1, 3, 4, 5, 12 and by interact): eighths/thirds for volumes and counts (⅜ cup, 1⅛ cups, ½ egg), grams rounded (to 5 above 20 g, 13 g below), "a pinch" never scales, singular/plural for cup/cups and egg/eggs. Steps toggle on tap (tick + strikethrough muted text), "N of 6 steps done" + ProgressBar, "All done — enjoy!".
- Host variables: title, description, ingN, unitN/unitsN (strings); prepMin, cookMin, baseServings, servings, amtN, kindN (0 count,1 volume,2 g,3 pinch), doneN (exported floats). Times formatted "1 h 15 min" when ≥ 60 (TimeChip). Note: `servings` starts at a literal 4, not at baseServings (an app sets both).
- Sizes: phone 380 wide scrolls; tablet (≥600 dp) shows Ingredients and Method side by side via a flow with computed panel widths; at 274 wide "Servings" ellipsizes to "Ser…" and long names wrap to many lines (below real phone widths).
- Themes: light/dark from theme colours only; mono-dark/mono-light: outline rings on chips/cards, filled discs for done steps, no colour reliance.
- Accessibility: servings group "Servings, 4, recipe is for 4" + "Decrease/Increase servings"; each step row "Step N. text" with state Done/Not done and clickable. Weak: ingredient amounts read as fragments ("1", "½", "cups", "Buttermilk"); step texts are also exposed as child texts (double reading possible).
- Bytes: 34.8 KB (expressions 12 KB: ~15 locals × 8 rows; TextChoice with 10 fraction glyphs per row; icons 4.4 KB). A static `kind` per row would drop the fraction machinery on weight/pinch rows (~5 KB).
- Known weak spots: kind is per-row host value so every row carries all branches; the 18 dead locals; fraction glyphs rely on font support (rendered fine in C++).
