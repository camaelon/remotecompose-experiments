# Eval 37, run 2: sales dashboard

Final document: `sales.json` (generated by `gen.py`), compiled to `sales.rc` (19,664 bytes).
Renders are in `out/`. The contact sheets I put together myself are `out/sheet1..5.png`.

## 1. Tool calls (20)
1. `list`: to see the servers and tools. Took the workflow: build_kit, then inline components plus check_component, then convert/render/audit. Decided to start with build_kit.
2. `build_kit` (verbatim goal): got BarChart, BigNumber, RankedList, StatTile and Icon, CMP-08 as the layout model, and design rules. Decided to use BigNumber (it already does money grouping, the signed and coloured change, the arrow, mono and its a11y text). BarChart has no current-hour highlight and RankedList has only one value per row, so I wrote my own versions.
3. `get BarChart definition`: the loop and arrayGet bar geometry, and how mono paints. Copied them into an inline HourChart (dimmed bars, the current hour drawn full on top, a peak label, 0/6/12/18 ticks, a dot under now).
4. `get RankedList definition`: the per-row canvas, textMerge semantics, textMeasure, and name shrink and clip. Copied them into an inline ProductList (revenue on line 1, units on line 2, a bar for the share of today's total).
5. `reference expressions`: confirmed `arraySum`, `timeInHr()`, step and ifElse, and the 32-entry limit.
6. `reference query "host string variable"`: host strings are root `variable` commands with `vtype: string, export: true`.
7. `convert`: **failed**. `$if names '0,6,12,18', which is not a parameter`. `$each` only takes a param name, so I made `ticks` a list param.
8. `convert`: **failed**. `text without a profiles header tag — add "profiles": 513`.
9. `reference query "header profiles fitBox"`: got the header shape. Found nothing on fitBox options.
10. `convert check`: OK, 14,189 bytes, host variables listed.
11. `render variants` (clock 14:30): 12 images. The design looked right, but the content sat vertically centred. Short and wide sizes dropped the products and showed only the number and a huge chart.
12. `render variants` after adding top alignment plus "wide" and "medium" layouts: top alignment worked. fitBox picked the wide row at 360x384 and 259x384, which squashed the product names to 3 letters. Removed the wide layout and kept full, medium, compact and minimal.
13. `render samples` (record, below yesterday, long name): below yesterday showed a red −30.3% with a down arrow. The long name shrank and clipped, **but the short names in the other rows shrank to 80% too**. My "record" sample summed to only 822,850 (my own mistake).
14. `render samples` at 09:15 (slow morning): fine. The change reads −98.7% because the comparison is against yesterday's full day (see section 5).
15. `render` of the library RankedList with one long name: **the library component has the same bug**. Every row's name is scaled to 80% once one row is long.
16. `render samples`, after turning each row into its own `ProductRow` component call: the bug is gone, because named canvas variables are now per call. The record day shows $1,152,000 (+17.6%).
17. `audit`: 0 errors, 0 warnings. One info note says which fitBox child is shown.
18. `inspect accessibility`: total and change are one item ("Today's revenue, $31,350, up 5.2 percent"). The chart reads "Revenue by hour today, from 0 to $6,230 per hour, current hour 14:00, $3,150 so far". Each product reads "Number 1, Wireless earbuds, 312 units, $9,720, 31 percent of today".
19. `render` 320x160 mono-dark with samples: the compact widget layout works, 7 digits shrink to fit, and the arrow and sign carry the change in mono.
20. `convert` (final): 19,664 bytes, OK.

## 2. Dead ends and wasted calls
- Calls 7 and 8 (and 9) were spent on failed converts. A minimal skeleton in build_kit (header with profiles 513, and `components` and `root` shape) would have avoided both. So would a note that `$each` cannot take a literal list.
- Call 12: I tried a side-by-side "wide" layout. fitBox picks the first child that *fits*, not the one that looks right, so the row won at narrow sizes. Better to know in advance that fitBox only tests height and minimum width.
- Call 13's record sample was wrong (my arithmetic). A render result that printed the computed total, or any named variable, per sample would have caught it.
- Calls 13 and 15 found a real library bug, so they were not wasted, but no tool flagged it.

## 3. Wrong, misleading, noisy or missing in tool output
- **RankedList long-name bug.** Its pitfall says "A long name shrinks to 80 % to fit before the value and is then clipped". In practice *every* row shrinks once any row is long, because `nw`/`ns`/`room` are shared named variables across the `$each` rows. The render said `findings: none` even though the text was visibly clipped. The "text cut off" check misses drawn text.
- The BigNumber pitfall is good, but neither BigNumber nor the build_kit design rules warn that "today so far vs yesterday's full day" makes a misleading percentage early in the day (−98.7% at 09:15). For a sales dashboard that is the main semantic trap.
- build_kit returned TIM-13 (tides) as an example because of the word "today". That is 6 KB of irrelevant JSON. `unmatched_terms: ["sale", "product"]` even though RankedList's synonyms include "top products" and BigNumber's include "sales total".
- The `$each` error `$if names '0,6,12,18', which is not a parameter` says `$if` when the construct was `$each`.
- The convert failure "text without a profiles header tag" only appears after a failed convert. The header is never shown in build_kit.
- fitBox: I passed `verticalAlignment`/`horizontalAlignment` and nothing confirmed or rejected them. Content did become top-aligned, but I can't tell whether it was from these keys.
- The render variants list prints 12 separate PNGs with no combined sheet, so I had to build my own contact sheets.
- The ANIMATED_FLOAT (108) and LoopOperation (20) counts in convert's `ops` are unexplained noise for a static dashboard.

## 4. What I would have liked
- A document skeleton (header, resources, components, root) in build_kit's output.
- A `sheet: true` default for variants and samples (the render schema lists `sheet`, but nothing told me what it does with variants).
- Per-sample values of chosen variables (total, change) printed next to each render.
- A drawn-text clipping finding, and a lint for named canvas variables reused across `$each` iterations.
- A BarChart `highlight` index param, and a RankedList with a second value (units and revenue). Both are common needs for this request.
- fitBox docs: which attributes it takes, and how "fits" is decided.

## 5. Assessment of the result
- **Correctness:** today's total is `arraySum(@hourly)`. The change is `(total − yesterday) / yesterday × 100`, signed, green up or red down, with an arrow. The current hour is `timeInHr()`, and the clock-driven highlight follows the clock (checked at 09:15, 14:30 and 21:30). The share bar is product revenue / today's total.
- **Weak spot:** the change compares a partial day with a full day, as the spec asked ("yesterday's total"). It reads very negative in the morning. The app should send yesterday's revenue *up to the same hour* (or yesterday's hourly array, from which the document could sum the first `timeInHr()+1` hours). I'd raise this with the user.
- **Host variables:** `hourly` (24 floats), `units` and `productRevenue` (3 floats each), `yesterdayTotal`, and the strings `p1`, `p2`, `p3`. All are exported and have sensible sample values.
- **Sizes:** fitBox chooses full (phone/tablet), then medium (no title, shorter chart; 360x384, 576x480), then compact (number plus chart, used for a 4x2 widget at 320x160; it drops the products), then minimal (the number only). The tablet layout is just the phone column stretched, with empty space below.
- **Themes and mono:** only theme colours are used. Mono draws outline bars with the current hour filled, a filled rank-1 disc, and outline share bars. The change stays readable by arrow and sign.
- **Accessibility:** total and change are announced as one item, the chart with its range and the current hour, and each product with rank, name, units, revenue and share. The title and section texts are plain text.
- **Bytes:** 19.7 KB. Moving from the `$each` rows to three ProductRow calls cost about +5.5 KB, because each row's drawn texts are expanded in full; that was needed to fix the shared-variable bug.
- **Other weak spots:** long names are clipped with no ellipsis. Products are missing from the 4x2 widget. Hour labels are fixed at 0/6/12/18, with no label for the current hour beyond the dot. I did not publish a page, and the user's request did not ask for one.
