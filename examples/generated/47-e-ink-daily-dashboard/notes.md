## 2. Dead ends / wasted calls

- **TextChoice with an integer host variable (calls 7–10, one fix cycle).** I passed `index: "@code"` where `code` was bound to `@weatherCode`, an exported `integers` entry. It rendered "Sunny" (item 0) whatever the value; `textchoice1_k (int) = 0` appeared among host variables. TextChoice's doc says index is "a number, a "@variable" or an expression" with no caveat about integers. Avoided by: a pitfall/lint, or a doc example with an int variable. I switched to a stateLayout of five texts indexed by the same int, which works.
- **DateLabel (calls 10–20).** Used as build_kit suggested; it's drawn on a canvas, so a screen reader hears only its `label` ("Today's date"), not the date. The pitfall list mentions "the date is drawn, not a text node" but not that this loses the date for accessibility. Replaced by a layout text built with TIM-11's global-block technique (needed one more get).
- **wakeIn (calls 15–17, 2 wasted).** TIM-10's pitfall names `wakeIn` as something that schedules a repaint; the expressions reference doesn't list it and json2rc rejects it. Avoided by not mentioning it, or documenting how to use it.
- Call 9 (describe render) could have been skipped: the list text already mentions samples/clocks/variants, but not `sizes`.

Dead ends: 3 (TextChoice index, DateLabel accessibility, wakeIn).

## 3. Wrong, misleading, noisy or missing in tool output

- build_kit matched **"ink" → `capability:input.press`** ("e-ink" is a display type, not pressing). Also pulled STR-09 "modifier macros" into the kit for that reason. Nothing in the kit about mono-light, although the request is literally "e-ink … black and white"; I found `componentTheme: "mono-light"` only in reference components.
- build_kit `layout_model` = CMP-08 Gauges and KPI tiles: not a reasonable model for a text dashboard.
- `"quote"` unmatched; no example of host strings, empty-state lists or agenda rows in the kit (reference format had host strings, cited as HST-01).
- TextChoice + int variable silently shows item 0 (see above). `convert` lists `textchoice1_k (int)` etc. as "Host-settable variables" — internal, noise and misleading.
- DateLabel accessibility: only the static label is spoken. Its "label" param doc ("Accessibility label (the date is drawn, not a text node)") doesn't say the label can't contain the date, and the component offers no way to.
- Repaint: DateLabel pitfall "The date changes at midnight with no repaint of its own" is correct, but there's no supported way to schedule one daily repaint: TIM-10: "only continuousSec, timeInSec, timeInMin and wakeIn do" — `wakeIn` → "Unknown token in expression: wakeIn".
- The render size warning repeats in every render: "at 800×288 and 576×480 the content no longer fits … A widget is resized by its host" even when I passed explicit `sizes` (a fixed e-ink panel isn't a resizable widget). Noise for fixed-size targets.
- render's description says "a single render is DARK unless theme: light", but with `componentTheme: "mono-light"` in the document the dark variant is white — correct behaviour, but the doc doesn't mention a document-level componentTheme overrides it.
- `render` with `samples`/`sizes` writes N separate PNGs; no contact sheet, so I stacked them myself (check_component has a sheet, render does not).
- Row of bold time + regular title with `verticalAlignment: "top"`: the bold time sits ~3 px lower than the title (a11y shows time box 32.2 tall vs 28). Not flagged by anything; unclear whether it's the renderer's text metrics.
- `autoSize` with `minFontSize` at 0.6× still clipped at 576 wide; render reported it as `text_overflow (clipped)` — good finding, but the text "autoSize: true (shrinks the font to fit its box)" doesn't say minFontSize wins over fitting.

## 4. What I'd have liked

- build_kit to recognise "e-ink"/"black and white" and return `componentTheme: "mono-light"` plus an e-ink example (fixed panel sizes, no animation, repaint policy).
- A documented way to repaint exactly once at midnight (a `wakeIn`/next-day timer), or an explicit statement that this must come from the host.
- A date component that is a layout text (accessible, follows font scale), or DateLabel speaking the date.
- A list/agenda component taking N host rows with an empty state.
- `render` contact sheet for samples × sizes, and a way to mark the document as a fixed-size panel so widget resize warnings stop.
- TextChoice to accept an integer variable (or lint it).

## 5. Honest assessment

- **Correctness:** date computed from the clock (weekday/month names cut from padded strings, day and year via textFromFloat); verified 31 Oct, 1 Nov (midnight rollover), 1 Jan 2027, 30 Sep (longest name). Weather condition (0 sun, 1 cloud, 2 rain, 3 snow, 4 storm) switches icon and name; high/low incl. negatives OK.
- **Host variables (12):** strings `a1Time, a1Title, a2Time, a2Title, a3Time, a3Title, quote, quoteAuthor`; floats `hi, lo, agendaCount` (0–3); int `weatherCode`. Weak spot: the app must keep `agendaCount` consistent with the strings it sends (stale strings for hidden rows are harmless).
- **Sizes:** stateLayout on window: landscape (w > h) header row date + weather, agenda | quote below; portrait stacked with the quote at the bottom; shelf label (height < 200) date + compact weather (icon + "14° / 6°") + first agenda item or "Nothing scheduled". Checked at 800×480, 640×400, 480×800, 296×128. Square 480×480 and short sizes overflow (portrait layout chosen) — out of scope for fixed panels but a weak spot. Date uses autoSize, so its size varies with the day's name length (≈ 26–40 px landscape).
- **Black and white:** componentTheme mono-light; pixels are white, black, one grey (#616161 for the "Agenda" heading) plus anti-aliasing. The weather icons use mono outlines. Dark system theme still renders white (forced).
- **Repaint:** idle — nothing in the document schedules a repaint; host variable changes redraw it. The date rolls over only at the host's next redraw: **the host must trigger a redraw at midnight** (no in-document daily timer was found; timeInMin would cost a repaint a minute). No animation.
- **Accessibility:** header contentDescription; date, condition, temperatures, agenda times/titles, quote and author are layout texts; weather icon labelled "Weather: Rain"; high/low has a spoken "High 14 degrees, low 6 degrees". Weak: icon label and condition text both speak the condition; agenda time and title are separate nodes, not merged per row; the quote icon is unlabelled decoration.
- **Bytes:** 14,814 B (three layouts each carry their own copies via inline components; the five WeatherIcons are drawn per layout).
- **Known weak spots:** time/title baseline offset of a few px; quote max lines (7 landscape / 6 portrait) truncate very long quotes with an ellipsis; the "99"-like quote icon is small; English-only names.
