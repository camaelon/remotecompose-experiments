# World clock widget: eval notes (02-run1)

Final document: `worldclock.json` (source, generated by `gen.py`), `worldclock.rc` (37,947 B), `worldclock.html` (playground).
Evidence renders: `sheet3.png` (themes/mono/sizes at 23:30), `sheet-clocks.png` (phone + map, 4 clocks), `sheet-tokyo.png` (user in Tokyo, DST samples), `sheet-small2.png` (small sizes across midnight), `out/`.

## 2. Dead ends and wasted calls (4)

- Call 4 (`get TIM-08`): the kit's snippets already had everything; the layout model is a tiny column. A "why this is the layout model" with the relevant structure in build_kit would have avoided it.
- Call 13 fixes: I used `contentAlignment` (a Compose habit) and `spacedBy` in a row with a weighted child. The components guide does say "Weights ignore spacedBy", but in a trap list I read after writing the row; build_kit's design rules don't mention it.
- Call 16: phone list column with `{"height": 240}` and `verticalWeight` rows rendered with rows ~110 dp apart, with no finding. I switched to fixed-height rows (static param) instead of diagnosing. A layout/overflow finding there would have saved the guesswork.
- Calls 29–30: chasing the variants/publish "content no longer fits at 259×180" warning and the engines "drawn in TypeScript" report; both turned out to be false alarms.

## 3. Wrong, misleading, noisy or missing output

- **Wrong formula in build_kit's design rule "Time zones come from the app"**: "The difference from the user's time is (@offCity - (0 - offsetToUtc() / 60)) / 60 hours." That's `(@offCity + userOffset)/60`. The same rule (and MAP-01) say `utcMin = timeInMin() - offsetToUtc() / 60`, so offsetToUtc() is the user's offset east of UTC and the difference is `(@offCity - offsetToUtc()/60)/60`. With the kit's formula, a Tokyo user would see London at +9 h instead of −9 h. Verified by render as a Tokyo user (call 19).
- Vocabulary noise in build_kit: "difference" → `draw.path-ops` (then listed as `not_covered`); "night" → `theme.mode` and WeatherIcon; icon suggestion for "local time" is `local_shipping` and for "difference" the `difference` icon. None of this applies.
- `render variants` / `publish` header: "size warning: at 360×108 and 259×180 the content no longer fits (cut off or squeezed to nothing)". But the per-variant lines for those sizes say "findings: none" and the images are fine. It's unclear what triggers this, and publish repeats it.
- `zero_size` warning "4 visible component(s) got no size from the layout, so they draw nothing" for a row whose children are all intentionally GONE (no "+1 day" today). That's an expected state but it's reported as a warning.
- `inspect engines`: "empty in C++, drawn in TypeScript" for texts that TS's own layout reports as "HIDDEN (not drawn)". This is a false alarm about the very player the playground uses.
- WorldMap doc: "a world at low detail is ~3.5 KB"; inspect bytes shows a 5,681 B PathData (plus 857 + 473 B).
- `render variants` has no tall/phone size, though build_kit and the task call for phone screens. I had to render 360x640 separately to see the stateLayout's phone branch.
- The layout model TIM-08 hard-codes "29 Oct 2026 · 12:24:12 UTC" text, which the "Compute dates from the clock" rule tells you not to do. (It's the target, so it's defensible, but the audit's hardcoded_date would flag mine.)
- Accessibility: nothing explains how to say a live word (day/night) inside one merged description, short of the canvas `global` textSubtext trick, which is awkward per component call (shared variable names). Also nothing on how to keep a screen reader from also reading the visual fragments ("−", "4", " h") as separate nodes.
- No guidance on what a stateLayout with several full layouts costs. Each copy of 4 cities is ~6 KB, so five layouts end up at 38 KB.

## 4. What I'd have liked from the tools

- A correct, tested world-clock recipe: offsets as host floats, the diff formula, a day-delta formula, and a test recipe (`system_variables {"10": 32400}` + `samples` of offsets) in the time-zone rule.
- A `phone` (tall) size in `variants`, or a way to add sizes to variants.
- A semantics "merge children / hide descendants" option, or a text-choice that can live inside a textMerge, for one announcement per city.
- Warnings that are aware of visibility (GONE children), and an engines diff that ignores hidden nodes.
- A note in the kit that a weight plus spacedBy overflows (it is the most common row shape).

## 5. Assessment of the final widget

- **Correctness**: local times, "same time" / "+9 h" / "−4 h", "+1 day" / "yesterday" and day (06:00–18:00) / night icons are right at London 08:00, 23:30, 01:30 the next day, Dec 31 23:59, and as a Tokyo user at 07:00. Day/night uses a fixed 6–18 rule, not real sunrise. Fractional offsets (India +5:30, Adelaide) would show the hour difference rounded/truncated with no minutes: weak spot.
- **Host variables**: `off_lon`, `off_nyc`, `off_tyo`, `off_syd` (minutes east of UTC, DST included) must be sent by the app. The document has no time-zone database, so the defaults (0, −240, 540, 660: true for 31 Oct 2026) go stale at the next DST change (NY on 1 Nov) unless the host updates them. The DST change itself is correct when the host sends the new offset (checked with samples −240/−300, London 0/60, Sydney 660/600). The user's own offset comes from offsetToUtc().
- **Sizes**: a stateLayout on window size. 4x2 (and wide or tall widgets, ≥260 wide): 4 rows (icon, name, diff, big time). Narrow (2x2): 2x2 tiles. Short and wide (4x1): a 1x4 strip of tiles. Narrow and short: compact tiles (time only). Phone (height ≥300): title, WorldMap with the night shade and the 4 cities, then the rows. On a wide 576x135 the tiles sit at the top with empty space below.
- **Themes/mono**: only theme colours; light, dark, mono-dark and mono-light checked. Day/night reads in mono by shape (sun vs crescent).
- **Repaint**: scheduled once a minute (timeInMin); no animation.
- **Accessibility**: header description. Each city's visible day/night icon box carries "London, 23:30, night, 0 hours from your time" (live). The visible texts are also read, with the diff in fragments. The description omits "+1 day" / "yesterday" and says "-4 hours" rather than "4 hours behind".
- **Bytes**: 37,947 B. It's large for a widget because each of 5 layouts writes out the 4 cities and the WorldMap is ~7 KB. Dropping the strip/compact variants or the phone branch would roughly halve it.
- **Engines**: the renders are C++; the TS layout (inspect) agrees on visibility. I didn't eyeball the playground in a browser.
