# Rating card: notes

Final deliverable: `card.json` (generated by `gen3.py`) and `card.rc` (6,488 B). Renders are in `out/` (`final_light-sample1..4` = ratings 0/1/3/5, `final_monoinv-*`, `final_phone_dark.png`, `v3-*` = all variants, `sheet.png` = contact sheet). `gen.py` and `gen2.py` are earlier versions.

## 1. Tool calls (25)

1. `list`: to see the servers and tools. It says to start with build_kit and lists the workflow, so I used only the `remotecompose` server.
2. `build_kit` with the request verbatim (kit.txt): it suggested Card, **Rating**, **TextChoice** ("poor to excellent" is a synonym), and the design rules. The "Taps reach the app" rule says to use an exported variable plus a hostNamedAction. Rating's pitfall says every star gets the same a11y label. Decision: write my own star component so each star can be labelled "N stars".
3. `get Rating definition:true`: I copied its canvas body (Material star path, alpha step).
4. `get Button`: `enabled` takes a runtime 0/1 resources expression, which is exactly what Submit needs.
5. `reference format`: got the syntax for host strings (root `variable` command), exported resources variables, hostNamedAction with `value:"@rating", valueType:"float"`, semantics with textMerge, and widget sizes (4x2 = 320x160, hosts 250x110 to 360x190).
6. `convert check:true` on v1 (Card + 5 RateStar calls + TextChoice + Button): OK, 5,138 B. It warned `shared_action_name` because all stars used "rate". Decision: rename to rate1..rate5, each carrying @rating.
7. `inspect interact` with `{"tap":{"target":"4 stars"}}`: **dead end**. My action shape was wrong, and the tool said only `handled:false` / "no difference" instead of rejecting it.
8. `describe inspect`: the action shapes are `{target: index}` and `{tap:[x,y]}`.
9. `inspect interactions`: star target indices 0..4. Submit was absent while disabled, which is correct.
10. `interact target 3` + include_layout: rating 4, host action rate4=4, "Very good" visible, canSubmit 1. I also got Submit's bounds. It reported `repaint: "continuous"` after the tap (ripple?).
11. `interact` tap on Submit with no rating: no effect, no host action. Correct.
12. `interact` star4, star4, star2, Submit: rating 2, actions rate4=4, rate4=4, rate2=2, submitRating=2. Correct.
13. `render samples` 0/1/3/5 (light): all looked right.
14. `render variants`: short and 4x1 sizes gave zero-size warnings, and "Tap a star" was clipped. In dark mode the empty stars (outline colour) had low contrast. Decision: add a compact layout and use `@colors.muted` for empty stars.
15. `render variants` on v2 (stateLayout with compact/regular alternatives): NOT DONE. `shared_action_name` again, because both alternatives contain the stars and Submit. **Dead end**: duplicating interactive content across alternatives is incompatible with distinct action names. Decision: one tree, with the question/word placement switched by visibility and Submit kept beside the stars.
16. `render variants` on v3: error. TextChoice takes no `modifiers` (I had put visibility on it). **Dead end**, caused by the format reference (see 3).
17. `render variants` on v3 after wrapping it in a box: no findings anywhere. The images look good at 320x160, 512x120 and 320x96. 230 wide gives small stars. 160x96 is unusable and 320x80 clips Submit, but neither was reported.
18. `render samples` 0/1/3/5 light, final: correct.
19. `render componentTheme mono-inverted` samples 0/3: legible. Disabled Submit is outlined and enabled Submit is filled black.
20. `render` phone 411x891 dark, rating 4, longer question: fine. Info `unused_space` (noise for a centred card).
21. `inspect accessibility` at rating 4: stars "1 star".."5 stars", row "Rating, 4 of 5 stars", the word "Very good" as text, Submit labelled.
22. `audit`: 0 errors and 0 warnings. One info: touch target 40 < 48.
23. `interact` on final: disabled Submit tap, star4, star4, star2, Submit. Same correct result as call 12.
24. `interact` on final: star4 → rating 4, rate4=4, both TextChoices at index 4.
25. `convert check:true` final: ok, 6,488 B.

## 2. Dead ends and wasted calls (3)

- Call 7: I guessed the interact action shape. Reading `describe inspect` first would have avoided it, and the tool should reject unknown action shapes.
- Call 15: I used stateLayout alternatives for compact/regular, as the design rule "Adapt to the size" suggests. That duplicates interactive controls and trips `shared_action_name` (U58). Nothing in the size guidance warns that alternatives with host actions collide.
- Call 16: I put `visibility` on a TextChoice call because the format reference says visibility works on "Any component ... (text, box, canvas, a component call)".

## 3. Wrong, misleading, noisy or missing output

- Format reference: "visibility ... Any component takes it (text, box, canvas, a component call)". This is false for TextChoice (and probably any library call): "a component call takes its params only".
- The Rating component's onClick doc invites `[{"type": "hostNamedAction", "name": "kitchenLight"}]`. That action is appended to every star, which is exactly the shared-name case the converter then flags. The component cannot send one rating action correctly. Its pitfall also admits that per-star labels ("N stars") are impossible.
- Design rule "Adapt to the size" recommends fitBox/stateLayout alternatives without mentioning that each alternative's host actions are separate controls (shared_action_name / U58).
- `interact` silently accepted `{"tap":{"target":"4 stars"}}` and returned "no difference". It should be an error. A tap by accessibility label would be nice.
- `render variants`: "findings: none" for 160x96 (stars 8 dp, question "How...") and for 320x80 (Submit cut at the bottom edge). The v1 run did report zero_size there, so v3's overflow went unnoticed.
- The same TextChoice error was repeated 11 times (once per variant): noise.
- Touch target: the Rating pitfall says "40 dp touch-target guideline", while audit uses 48×48. Pick one.
- `inspect accessibility` puts Submit at x 241..320, past the card's 304 inner edge, while the render shows it inside. The bounds look inconsistent between engines.
- `convert` says "6 click target(s)" while interactions lists 5 when Submit is disabled. Minor.
- After a tap, interact reports `repaint: "continuous"` with no explanation (ripple?).
- Phone render: `unused_space` info for a centred card. Noise.
- The `interact` step reports `"label": null` for the stars even though they have semantics labels.

## 4. What I would have liked

- A Rating option for per-star labels (a list param such as `labels`) and a single host action carrying the value (e.g. an `onChange` sent once).
- A way to declare a host action name once (globally) so several controls can share it, or a documented pattern for "one action, many triggers".
- interact taps by label/text; strict validation of action objects.
- Variants that also flag clipping/overflow against the window (the 4x1 Submit clip).
- An a11y "selected/state" option for the star buttons (stateDescription) with documented syntax.

## 5. Assessment of the final card

- **Correctness/interactions (verified with interact):** tapping star N sets rating = N, exported, and sends `rateN` with value N. Tapping the same star again keeps it. The word follows: Tap a star / Poor / Fair / Good / Very good / Excellent. Submit is disabled at 0 (a tap does nothing, it is announced as disabled), and once a rating exists it sends `submitRating` with the value. Action names are rate1..rate5 rather than one "rate". The app must route five names, each carrying the value. This is a workaround for the shared-name trap.
- **Sizes:** 4x2 320x160 is good and 360x190 is fine. At 320x96 / 512x120 (short) it switches to a compact layout with the word beside the question. At 250–230 wide the stars shrink to about 26–22 dp touch boxes (they are 40 dp at 320). 160 wide and 320x80 (4x1) are not supported. On a phone the card is centred and fills the width.
- **Themes:** light and dark use only theme colours. Empty stars are `muted` for contrast and lit stars are `highlight`. Mono and mono-inverted are legible: filled vs outline stars, and outlined (disabled) vs filled (enabled) Submit.
- **Accessibility:** the stars are labelled "1 star".."5 stars". The star row announces "Rating, N of 5 stars", and the word is a visible text. The stars carry no "selected" state, and the word is not a live region (not announced on change unless re-focused). Star targets are 40 dp at 320 wide (audit info: < 48).
- **Bytes:** 6,488 B. The two question texts and two TextChoices are duplicated for the compact/regular switch.
- **Weak spots:** small star targets below 320 wide; five action names; no 4x1 layout; a11y bounds disagree with the render.
