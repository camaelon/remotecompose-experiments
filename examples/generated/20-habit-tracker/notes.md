# Habit tracker (5 habits, this week, streaks) — eval notes, prompt 20 run 2

Final: `habits.json` (generated by `build2.py`, which reuses helpers from `build.py`/`gen.py`) -> `habits.rc` (16,200 B).
Phone renders: `sz-size-412x892.png`, `sz-size-360x640.png`, `phone-dark-tue.png`; 4x2 widget renders: `v5-*.png`; samples: `s4-sample1..5.png` (phone, from before the last row-height change).

## Host data contract
- `h0..h4` host strings (habit names; root-level `variable` commands, export).
- `m0..m4` host floats: this week's days as a **bitmask**, bit 0 = Monday ... bit 6 = Sunday (e.g. 31 = Mon-Fri done). Bits after today are ignored when drawing.
- `s0..s4` host floats: streak **through yesterday**. The displayed streak = s + today's bit, so checking today adds one at once.
- Tap on today's circle: `m_i += 2^(weekDay()-1) * (1 - 2*todayBit)` (flips only today's bit), then `hostNamedAction "toggleToday<i>"` with the new mask as a float value.

## 2. Dead ends / wasted calls (3)
- Calls 9-10: `{"spacedBy": "@gap"}` collapsed every nested row to 0 wide with no error. format reference shows spacedBy only with a number but does not say a variable is refused; convert/render accepted it.
- Call 8 (partly): first design was 50 KB because each component local and each spliced param expression becomes its own FloatExpression per instance. Knowing that "a float param given an expression is re-spliced into every local" would have led straight to document-level per-day variables.
- Call 17: guessed the interact action shape. Describe-before-call would have avoided it.

## 3. Wrong, misleading, noisy or missing
- Variable in `spacedBy`: silently breaks layout (0-width rows) instead of an error/lint. The render finding blamed text: "13 text(s) wider or taller than their box and cut at the edge: \"M\" (clipped)...", which points at the wrong cause; zero_size was only visible in inspect layout.
- build_kit: "tracker" -> `map.marker` and pulled in MAP-03 (a flight map), irrelevant. "streak" unmatched. No needs_component for "a week strip of day checkmarks", although the library has nothing for it. Checkbox was proposed but a Checkbox is a labelled row, not a 7-day grid cell.
- Interact step result shows `"label": null` for targets that do have a contentDescription (accessibility shows "Drink water, today").
- interact's "repaint: continuous at the last step" while inspect runtime says "idle — nothing schedules a repaint": contradictory.
- The format doc says date-only documents do not repaint at midnight; fine, but build_kit's "Compute dates from the clock" rule does not mention that a week view will keep showing yesterday's highlight until the host redraws.
- Paint is sticky (documented), so my tick inherited alpha by luck in v1 and lost it after I reordered; check_component's 6-state sheet (call 7) didn't show it because it was on a light background with done=1/0 only... it did show, but faintly. A lint "paint alpha left from a previous op" would not help; just noting the trap.
- render variants writes images next to output_path with suffixes (fine) but `out/` gets extra `render-*.png` files from check_component nobody asked for.

## 4. What I would have liked
- A lint (convert/check_component) for modifiers that accept only numbers (spacedBy, padding, size) when given "@var" or expressions.
- check_component / convert reporting expressions per instance ("each call adds 16 FloatExpressions; 9 are identical across calls — hoist them").
- A library "WeekStrip"/"DayDots" component (seven day states + today highlight), common for habit/fitness widgets.
- A way to make an action/label shared per row instead of re-spliced into each of 7 cells.
- interact steps reporting the target's accessibility label.

## 5. Assessment of the final screen
- Correctness: day states decoded from the bitmask; today from weekDay() (verified Saturday and Tuesday clocks); future days are dots; streak = host + today bit.
- Interactions: only today's circle per habit is clickable (5 targets); tap flips that habit's today bit and sends `toggleToday<i>` with the new mask; past days unhandled. Verified at 320x160 and 412x892.
- Sizes: 4x2 (320x160) fits all 5 rows, title and hint collapse away; phone shows title, header, 5 tall rows and a hint (bottom ~35% still empty). 230 wide works with ellipsized names; 2x2 and 160x96 are not supported (streak cut). Short 320x96 drops rows 3-5 (no "more" indicator).
- Themes/mono: light, dark, mono-dark, mono-light all correct; state shown by shape (filled+tick vs ring vs dot), today by a ring and a filled letter pill.
- Accessibility: header description; each row announces "name: N of D done this week so far, streak S" (D = days elapsed); today's circle labelled "name, today" with state Done / Not done. Weak: "streak 1" without "days" (dropped to avoid "1 days"); no role; touch targets 17 dp on the widget (< 48 dp).
- Bytes: 16.2 KB (from 50.5 KB in v1). Still ~260 expressions evaluated per frame (idle document, so no cost when static).
- Weak spots: the week does not roll over at midnight by itself (needs host redraw); bitmask representation needs the host to reset at the start of the week; long names are ellipsized, not wrapped; streak in light theme uses warning orange (fine) but in mono it is just white.
